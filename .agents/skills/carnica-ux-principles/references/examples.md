## §1 Loading / empty / error — три состояния обязательны

Конкретный экран: **история транзакций** (`/transactions`).

### Loading state (данные загружаются)

- **Что показать**: `skeleton 2.1` — повторяет layout cell-списка (40px circle + два прямоугольника текста + chevron).
- **НЕ показывать**: спиннер по центру экрана без skeleton — пользователь видит «пустоту» и не понимает структуру.
- **Длительность**: skeleton показывается весь период загрузки (даже если 200ms — не «мигай»).
- **Анти-паттерн**: запускать fade-in контента поверх скелетона без crossfade — рывок.

### Empty state (данных нет)

- **Что показать**: иллюстрация (`error_empty state 3.0` с view=empty) + текст «у вас пока нет транзакций» + CTA «совершить первую покупку».
- **Текст**: строчными (см. §15), без точки в конце.
- **НЕ показывать**: пустой список или пустой контейнер без объяснения причины.
- **Цель CTA**: дать пользователю action — куда идти дальше.

### Error state (ошибка загрузки)

- **Что показать**: иллюстрация (`error_empty state 3.0` с view=error) + текст «не получилось загрузить транзакции» + кнопка «повторить» (`button 2.5` priority=primary).
- **Текст ошибки**: понятный пользователю, без технических кодов («сетевая ошибка 503» — плохо; «нет интернета, проверь соединение» — хорошо).
- **НЕ показывать**: кэшированные старые данные с пометкой «возможно устаревшие» — это путает.

**Тест готовности экрана**: для каждого экрана с данными ответь на три вопроса — «что я вижу пока грузится / что я вижу когда данных нет / что я вижу когда упало». Если на любой вопрос ответа нет — экран не готов.

## §10 Edge alignment — 4px vs 20px (card-holder стопка)

Стандартный side-padding **20px** от края экрана. Card-holder стопка (wallet screen) использует **4px** — исключение.

### Стандарт: 20px

```
┌─ screen 375 ─────────────────────┐
│ [20px][═══ content 335px ═══][20]│
│                                  │
│  ┌─────── card ───────┐          │
│  │  cell row          │          │
│  │  cell row          │          │
│  └────────────────────┘          │
└──────────────────────────────────┘
```

Применяется к: cell-спискам, обычным карточкам, формам, кнопкам, секциям главного экрана.

### Card-holder: 4px от края (wallet screen)

Selected card + 3 collapsed cards снизу. Конкретные размеры для viewport 375px:

| Позиция в стопке | Ширина | Top | Cornerradius | Shadow | Padding |
|---|---|---|---|---|---|
| Selected (wrapper px=4) | 367 | 123 | 32 | нет | 16 |
| Collapsed #1 (дальняя) | 297.27 | 712 | 25.92 | нет | 12.96 |
| Collapsed #2 (средняя) | 330.3 | 722 | 28.8 | y=-2, blur=10, 8% | 14.4 |
| Collapsed #3 (ближняя) | 367 | 732 | 32 | y=-2, blur=10, 8% | 16 |

Центрирование каждой card: `card.x = (375 - card.width) / 2` → `x = 39 / 22 / 4` соответственно.

**Технически (Figma Plugin API)**:
- Main frame: `primaryAxisSizingMode = 'FIXED'`, `height = 812`, `clipsContent = true`, auto-layout VERTICAL
- Collapsed cards: `main.appendChild(card); card.layoutPositioning = 'ABSOLUTE'`
- Масштабирование содержимого узких карт: `scale = card.width / 367`

**Визуальный эффект**: selected card «лежит сверху», collapsed формирует стопку с нарастающим объёмом. Клиппинг обрезает низ — видно только верхние ~80px ближней карты. Пользователь понимает, что под выбранной картой есть другие аккаунты.

**Когда применять 4px**:
- Card-holder стопки (wallet, multi-account screens)
- Full-bleed промо-баннеры на главном
- Некоторые блоки внутри модальных окон
- НЕ применять для cell-списков, обычных карточек, форм — там 20px.

## §12 Dots progress LTR — правильно vs неправильно

Прогресс-бар = ряд маленьких кружков (~6px диаметр, gap ~3px) под числовым значением. Жёлтые точки = remaining (доступное), серые = consumed (потраченное). **Направление: слева направо.**

### Пример: 12 точек, 7 remaining

```
remaining = 7, total = 12, columns = 12
threshold = Math.round(7 / 12 * 12) = 7

✅ Правильно (LTR, по колонкам):
●●●●●●● ○○○○○      ← жёлтые 1-7 слева, серые 8-12 справа
└─────┘ └───┘
remaining  consumed
```

### Анти-паттерн: разделение по рядам

```
❌ Плохо (по рядам):
●●●●●●○                  ← верхний ряд: 6 жёлтых + 1 серая
○○○○○○                   ← нижний ряд: всё серые

Почему плохо: пользователь не понимает направление progress.
Нет ясной семантики «слева — то что есть, справа — то что потрачено».
```

### Threshold формула

```js
const remaining = 7;
const total = 12;
const totalColumns = 12; // обычно совпадает с total для линейного прогресса

const threshold = Math.round(remaining / total * totalColumns);

// Раскраска:
for (let col = 1; col <= totalColumns; col++) {
  if (col <= threshold) {
    // жёлтая точка (brand/primary #FFC800 или content/primary)
  } else {
    // серая точка (background/secondary или content/tertiary)
  }
}
```

### Где применяется (фирменный приём Beeline)

- Главный экран: остаток гб, минут, SMS
- Экраны детализации тарифа
- Не стандартный Carnica-компонент — собирается вручную из ellipse-элементов через Figma Plugin API

**Конкретные значения**:
- Ellipse diameter: ~6px
- Gap между точками: ~3px
- Залитая (remaining): `brand/primary` #FFC800 или `content/primary` #28303F
- Пустая (consumed): `background/secondary` #FFFFFF или `content/tertiary` #8E99AF

## §15 Lowercase UI — таблица примеров

Все UI-тексты строчными. Исключения: имена, бренды (кроме «билайн»), география, аббревиатуры (eSIM, SMS, QR), собств. названия в кавычках.

| Категория | ❌ Плохо | ✅ Хорошо | Почему |
|---|---|---|---|
| Заголовок секции | `ИТОГ ЗАКАЗА` | `итог заказа` | CAPS = визуальный шум |
| Кнопка | `ОФОРМИТЬ ЗАКАЗ` | `оформить заказ` | tone-of-voice близкий |
| Тэг | `Отсканируйте камерой` | `отсканируйте камерой` | UI всегда строчными |
| Пункт меню | `Безопасность` | `безопасность` | без ручной капитализации |
| Описание (1 строка) | `Мы отправили чек.` | `мы отправили чек` | точка в конце не ставится |
| Описание (2+ строки) | `Обычно 8 дней. Точная дата в SMS.` | `обычно 8 дней. точная дата в SMS` | точка только как разделитель внутри, после неё — строчная |
| Цена с маской | `Карта ·· 4242` | `карта ·· 4242` | строчная даже для «Карта» |
| Дата | `Оплачен 23 апреля, 15:14.` | `оплачен 23 апреля, 15:14` | без точки в конце |
| Бренд (другой) | `сбербанк` | `Сбербанк` | бренд = исключение |
| Бренд (Beeline) | `Билайн` | `билайн` | особое правило — билайн строчной |
| Аббревиатура | `смс` | `SMS` | аббревиатура заглавными |
| Имя | `илья абрамов` | `Илья Абрамов` | имя — исключение |
| География | `москва` | `Москва` | город — исключение |
| Собств. название | `тариф вверх` | `«Вверх!»` | название в кавычках с заглавной |
| Заголовок FAQ | `Когда привезут?` | `когда привезут?` | вопрос тоже строчными |

### Что запрещено в CSS

```css
/* ❌ Плохо */
.button-label {
  text-transform: uppercase;       /* CAPS через CSS */
  letter-spacing: 0.15em;          /* имитация CAPS через tracking */
}

/* ✅ Хорошо */
.button-label {
  /* пиши текст сразу строчными в HTML/JSX */
  /* без uppercase, без letter-spacing */
}
```

### Особый случай: «билайн» строчной

Бренды-исключения сохраняют заглавную (МТС, Apple, iPhone, Samsung, Steam, Xbox). Но **билайн** — всегда строчной, это часть фирменного tone-of-voice. Пишется так в собственном продукте и во всех маркетинговых материалах.

## §16 Tag tones — какой когда использовать

`tag 2.3` имеет 5 разрешённых tones. Цветные `surface-*` токены запрещены как фоны тэгов.

### Разрешённые tones — таблица применения

| Tone | Когда использовать | Пример текста | Фон | Цвет текста |
|---|---|---|---|---|
| `default` | Нейтральная метка, атрибут, категория | «отсканируйте камерой», «раздача интернета» | `#F0F3F5` серый | `content/secondary` |
| `brand` | Промо, акция, CTA-акцент | «акция -30%», «в рассрочку 0%», «новый» | `#FFC800` жёлтый | `content/primary` |
| `invert` | Сильный контраст на светлом фоне | «эксклюзив», «премиум» | `#28303F` тёмный | `content/invert` (белый) |
| `success` | Позитивный статус | «подключено», «доставлено», «сохранено» | `#CBF6E3` бледно-зелёный | `text-success-primary` |
| `error` | Негативный статус | «ошибка оплаты», «долг», «просрочка» | `rgba(248,74,0,0.12)` | `text-error-primary` |

### Запрещённые фоны — какие и почему

| Запрещённый токен | Hex | Где использовать вместо тэга |
|---|---|---|
| `surface-yellow` | #FFE999 | Icon-подложка 64-80px в карточке товара |
| `surface-green` | #CBF6E3 | Та же роль (подложка) |
| `surface-blue` | #D7EBFE | — |
| `surface-violet` | — | — |
| `surface-magenta` | — | — |
| `surface-teal` | — | — |
| `surface-orange` | — | — |
| `surface-red` | — | — |

Эти `surface-*` токены — для **больших цветных подложек** (illustration backgrounds, icon tiles в товарных карточках), НЕ для pill-тэгов.

### Anti-pattern: cветлый surface-token как фон тэга

```tsx
// ❌ Плохо: surface-* токен как фон тэга
<div className="bg-surface-yellow px-3 h-7 rounded-pill">отсканируйте камерой</div>
<div className="bg-surface-green ...">доставлено</div>

// ✅ Хорошо: tag 2.3 с правильным tone
<Tag tone="default">отсканируйте камерой</Tag>
<Tag tone="success">доставлено</Tag>
```

### UX-обоснование (почему 5 tones, не больше)

Тэг — **акцент внутри контента**, не самостоятельная единица. Если он пастельный (фиолетовый, голубой, бирюзовый), он конкурирует за внимание с главным CTA и статусами. Палитра ограничена пятью семантически чёткими ролями:

- **Серый default** = «метаданные» (не требует внимания)
- **Жёлтый brand** = «промо/акция» (приглашение к действию)
- **Тёмный invert** = «премиум-метка» (сильный визуальный якорь)
- **Зелёный success** = «всё хорошо»
- **Красно-оранжевый error** = «проблема»

Остальные цвета не несут чёткого UX-смысла → не используются.

### Figma-ссылка

Компонент `tag 2.3` (key `50cca33a43e2f604470f08b6956052f4c058277a`). Variants `color`: `default on bg_*`, `brand`, `invert`, `success`, `error`. Variants `accent` и `custom` — **не использовать** без явного согласования с дизайнером.
