## Порядок генерации

**Функциональные эталоны (compliance)** от простого к сложному: GS-4 → GS-2 → GS-1 → GS-5 → GS-3.

**Mood-эталоны (вкус и приёмы)** — после функциональных, в любом порядке: GS-9 (states) → GS-8 (feed) → GS-6 (тёмный hero) → GS-7 (info-dense) → GS-10 (motion).

Mood-эталоны оцениваются по `rules/critique.md` (6 измерений), не только по `rules/qa-scorecard.md`.

# Mood-эталоны (GS-6..GS-10)

GS-1..GS-5 — функциональные эталоны: ловят compliance с компонентами и правилами. GS-6..GS-10 — стиль-эталоны: ловят **вкус и приёмы композиции**. Они нужны, чтобы агент учился не только «что использовать», но и «как смотреть».

Главное отличие от функциональных GS:

- В таблице результатов акцент на **«какой приём здесь украден»**, а не «какие компоненты использованы».
- Оценка по `rules/critique.md` (6 измерений) обязательна, не только `rules/qa-scorecard.md`.
- Допустимо собирать на основе нескольких реальных макетов или без точного Figma node — в этом случае агент собирает эталон сам и согласует с дизайнером.

**Сложность:** Средняя
**Платформа:** APP или WEB

**Что на экране:**

- Тёмный фон (`#222731`) занимает hero-зону (mobile: 466px, desktop: 520–542px).
- Минимальный copy: 3–5 слов заголовок, 1 строка подзаголовка.

**Приём:**

- Контраст «весь интерфейс серый/белый — а здесь тёмный блок» создаёт фокус без необходимости в цветовых акцентах.
- Жёлтый CTA на тёмном даёт максимальную визуальную тягу.

**Ожидаемые компоненты Carnica:**
button 2.3 primary, опционально badge (для метки «новое»), text Approach E.

**Принципы из rules:**

- `.claude/rules/design-references.md §6` — баннеры (тёмный фон #222731 контрастирует с основным светлым).
- `anti-ai-slop.md → 20 % distinctive choice` — тёмная hero-зона как осознанный приём.

## GS-7: Info-dense dashboard (детализация расходов)

**Figma node:** `18377-31880` (упоминается в `.claude/rules/design-references.md §10`, файл `92rgddCR8pAQSGNjyAch9p`).
**Сложность:** Высокая
**Платформа:** APP

**Что на экране:**

- Stacked horizontal bar chart по категориям расходов (без круговых диаграмм).
- Легенда с цветными dot-индикаторами.
- Транзакции, сгруппированные по датам, в `cell 3.1` с tabular-nums числами.
- Отрицательные суммы — `error/primary` (#F84A00), без красного.

**Приём:**

- Высокая информационная плотность без потери воздуха: данные «упакованы», но между группами по датам есть gap 16–24px.
- `tabular-nums` обязательны — иначе колонки сумм «прыгают».
- 5 уровней иерархии допустимы — но через вариации `color`, не размеров (см. `.claude/rules/typography-principles.md §1`).

**Ожидаемые компоненты Carnica:**
navbar, cell 3.1 (с tabular-nums числами), divider, кастомные dots для легенды, кастомный stacked bar (не компонент).

**Принципы из rules:**

- `.claude/rules/design-references.md §10` — финансы/детализация: stacked bar + транзакции по датам.
- `.claude/rules/typography-principles.md §6` — `tabular-nums` для числовых колонок.

## GS-8: Editorial newspaper view (лента продуктов)

**Figma node:** часть GS-1 (`217-39898`), нижняя секция «другие продукты билайна».
**Сложность:** Средняя
**Платформа:** APP

**Что на экране:**

- Один белый блок (`cornerRadius: 32`), внутри — несколько секций.
- Над всей лентой — лёгкий заголовок-label `body/accent/small` (16/500), `content/secondary`, CENTER (не `title 2.1`).
- В каждой секции: визуальный якорь (ряд обложек/иконок), заголовок `body/accent/medium` (20/500) CENTER, описание `body/small` CENTER, CTA `button 2.3 secondary text`.
- Между секциями — `paddingTop: 24`, без divider.

**Приём:**

- Editorial-композиция: всё по центру, лёгкий иерархический ритм.
- Заголовок-label (CENTER, secondary) вместо `title 2.1` — приём, который даёт «продуктовый каталог» вместо «список фич».
- Asymmetric grids внутри якорей-обложек (см. §14 `ux-principles.md`).

**Ожидаемые компоненты Carnica:**
button 2.3 secondary text, кастомные обложки (image), text Approach E.

**Принципы из rules:**

- `.claude/rules/ux-principles.md §13` — продуктовая лента на главном экране.
- `.claude/rules/ux-principles.md §14` — асимметричная сетка карточек.

## GS-9: Empty / error / loading triplet

**Figma node:** TBD — собрать как **три состояния одного экрана** (например, «Мои подписки»).
**Сложность:** Средняя
**Платформа:** APP

**Что на экране:**

Три варианта одного и того же экрана в одном Figma-файле:

1. **Loading**: skeleton повторяет layout контента (cell-список с заглушками-прямоугольниками).
2. **Empty**: иллюстрация + текст «здесь пока пусто» + CTA «добавить первую подписку».
3. **Error**: иконка-ошибка + текст «не получилось загрузить» + кнопка «попробовать ещё раз».

**Приём:**

- Каждое состояние — отдельный экран с тем же navbar и тем же layout. Не overlay, не inline-сообщение.
- Skeleton повторяет реальный layout (не generic «3 строки серых прямоугольников»).

**Ожидаемые компоненты Carnica:**
navbar, skeleton 2.1, error_empty state 3.0, status screen 2.1, button 2.3.

**Принципы из rules:**

- `.claude/rules/ux-principles.md §1` — три обязательных состояния экрана с данными.
- `rules/component-decision-rules.md §6` — правильные компоненты для loading/empty/error.

## GS-10: Motion-эталон (переходы и микроинтеракции)

**Figma node:** TBD — собрать как **раскадровка** (3–5 кадров одного перехода).
**Сложность:** Высокая
**Платформа:** APP

**Что на экране:**

Раскадровка одного из переходов:

- **Bottom sheet up**: закрытое состояние → 50 % открыто → полностью открыто. Drag handle на каждом кадре.
- **Dialog appear**: pre-state → scale 0.95 + opacity 0 → final state. Overlay появляется до диалога.
- **Snackbar slide**: pre → выезд снизу + opacity 0 → final.
- **Stagger feed**: feed-секции появляются по 60–80ms друг за другом.

**Приём:**

- Mотion как часть дизайна, не как «потом разработчик докрутит». Длительности и easing зафиксированы в `rules/motion.md`.
- `prefers-reduced-motion` учтён: альтернативный кадр без motion (только opacity).

**Ожидаемые компоненты Carnica:**
dialog 2.1, action sheet 2.2, snackbar 2.1, feed-секции из GS-8.

**Принципы из rules:**

- `rules/motion.md` — Carnica-набор переходов (длительности, easing, prefers-reduced-motion).

## Workflow генерации одного sample

```
0. Прочитать canonical rules: rules/README.md → rules/workflow.md → rules/qa-scorecard.md
1. get_screenshot(fileKey: "GJXKeWvj14GIQ8EOw9Arac", nodeId: "<node>")
   → Зафиксировать визуальный образ эталона
2. get_design_context(fileKey: "GJXKeWvj14GIQ8EOw9Arac", nodeId: "<node>", depth: 4-5)
   → Зафиксировать компоненты, структуру, spacing
3. Составить component shopping list: key, import method, variants, TEXT/BOOLEAN/SWAP keys, gotchas
4. Сформулировать prompt на основе screenshot + context + shopping list
5. Сгенерировать через Figma MCP секциями, screenshot после каждой секции
6. get_screenshot результата → сравнить с эталоном
7. Оценить по 5 критериям (таблица ниже)
8. Если < 80% → repair iteration (до 3 попыток)
9. Сохранить результат в golden-samples/results/gs-N.md (N = 1..10)
10. Каждый новый вывод перенести в canonical rules/*
```

## Критерии оценки


| Критерий            | Описание                                       | Вес |
| ------------------- | ---------------------------------------------- | --- |
| Структура           | Правильная иерархия фреймов, auto-layout       | 30% |
| Компоненты          | Использованы правильные компоненты из Carnica  | 25% |
| Визуальное сходство | Общее визуальное впечатление совпадает         | 20% |
| Spacing             | Отступы, gaps, padding соответствуют reference | 15% |
| Типографика         | Правильные стили текста, иерархия              | 10% |


**Порог:** >= 90% = strong pass, >= 80% = pass, 60-80% = needs iteration, < 60% = fail.
**Целевой KPI:** все 5 samples >= 80%, минимум 3 samples >= 90%, GS-1 >= 85% за <= 3 итерации.
