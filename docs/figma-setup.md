# Подключение Figma для VK Social Commerce

Figma нужна только для задач, которые используют подтверждённые библиотеки, компоненты или макеты VK. Для работы с документацией и локальным React-кодом подключение Figma не обязательно.

## Текущий статус

Подтверждённые Figma-библиотеки и component keys VK пока не добавлены в репозиторий. До завершения аудита нельзя:

- считать случайно доступную библиотеку официальным source of truth;
- придумывать или публиковать Figma keys;
- заявлять соответствие дизайн-системе VK;
- создавать официальные токены и компоненты по визуальному предположению.

## Что понадобится

1. Доступ к согласованному Figma workspace.
2. Список библиотек и владельцев.
3. Подтверждение прав на использование материалов внутри проекта.
4. Документированные file keys и component keys без приватных данных.
5. Описание версий, режимов и областей применения библиотек.
6. Рабочее подключение Figma MCP для выбранного runtime.

## Порядок подключения источника

1. Зафиксируй название и владельца источника.
2. Проверь права доступа и допустимый способ хранения идентификаторов.
3. Определи, какие данные источник подтверждает: foundations, icons, components или patterns.
4. Добавь ссылку на source of truth в профильную документацию.
5. Проверь чтение нужных nodes и metadata.
6. Только после проверки используй данные в skills и прототипах.

## Правила безопасности

- Не коммить Figma access tokens и другие секреты.
- Не публикуй приватные внутренние ссылки без разрешения.
- Не копируй source data в несколько документов: назначь одного владельца.
- При недоступном источнике остановись и запроси доступ или данные.
- Любые ручные значения помечай как допущение, а не как официальный токен.

## Чек-лист аудита

- [ ] Определён владелец библиотеки.
- [ ] Подтверждены права использования.
- [ ] Зафиксирована версия источника.
- [ ] Проверены токены и modes.
- [ ] Проверены компоненты и variants.
- [ ] Проверены иконки и правила экспорта.
- [ ] Проверены продуктовые паттерны Соц-коммерции.
- [ ] Обновлены `docs/project-status.md` и профильные skills.

## Диагностика

| Симптом | Действие |
|---|---|
| Источник недоступен | Проверь доступ к workspace и запроси разрешение у владельца |
| Node или component key не найден | Проверь file version, branch и область публикации библиотеки |
| Данные расходятся между файлами | Останови работу и определи единый source of truth |
| Нет подтверждённых токенов | Не придумывай значения; зафиксируй блокер в `docs/project-status.md` |
